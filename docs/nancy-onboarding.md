## 七、开始改代码：改哪里

五个页面（`pages/` 下每个文件夹一个页面）：

| 目录 | 是什么 | 页面标题 |
|---|---|---|
| `pages/profile/` | 起点，选动作难点 | 衣适 |
| `pages/add/` | 添加衣服（拍照上传） | 添加衣服 |
| `pages/result/` | 分析结果 | 分析结果 |
| `pages/confirm/` | 购买确认 | 购买确认 |
| `pages/ideal/` | 理想款对比 | 理想款对比 |

每个页面里三个文件：

| 文件 | 管什么 |
|---|---|
| `index.wxml` | 界面上有什么 |
| `index.wxss` | 长什么样 |
| `index.js` | 点了之后干什么 |

其他常用位置：

| 想改什么 | 改哪 |
|---|---|
| 全局配色、字号、间距 | `app.wxss` |
| 云环境 ID、云函数名、兜底开关 | `utils/config.js` |
| 算分、格式化等纯逻辑 | `utils/*.js` |
| 本地存储、上传 | `utils/store.js`、`utils/upload.js` |
| 给模型的分析提示词 | `cloudfunctions/analyze/lib/prompt.js` |

## 八、改完怎么验

打开终端，进到 `yishi` 目录，跑：

```
node tests/run-all.js
```

7 个套件，每行末尾都要是 **0 失败**。

## 九、以后怎么同步代码

**拉取 Derek 的新改动：**

```
git pull
```

**把你的改动交上去：**

```
git add -A
git commit -m "改了什么，一句话说清楚"
git push
```

> `git push` 需要你先被加为这个仓库的 collaborator，没加会报 403。报 403 就先别管，只 `git commit` 保住改动，然后让 Derek 把你加上。

## 十、四条硬规矩

1. 优先用小程序自带组件：`view` `text` `button` `image` `checkbox` `radio` `picker` `switch` `navigator` `scroll-view`。官方已经提供的「行为」（勾选、点击热区、滚动、表单）不要自己重做。
2. 不要引第三方 UI 库（Vant / TDesign / uView）。
3. 界面文案不许出现「残障 / 残疾 / 病人 / 疾病」，一律说「动作不太方便」。
4. 纯逻辑写进 `utils/`，页面只负责渲染。

## 十一、你不用管的事

- 发布上线（只有管理员能做）
- 云函数部署、环境变量、开通云开发
- 服务器域名配置

- 扫码说没权限 → 回第二步
