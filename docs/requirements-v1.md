# 穿的顺 · 第一版需求

日期：2026-09-18  
状态：根据现有代码整理的实施草案；本文描述目标行为，不代表功能已经完成。执行进度见 [TODO](todo.md)。

## 1. 目标与用户

帮助为动作不太方便的家人选衣服的人，根据衣服照片和具体动作难点，识别可能影响穿脱的结构，并形成可以向商家确认的问题及收货后的试穿清单。

第一版的交付目标：用户可以用自己的照片完成一次真实分析，清楚知道哪些是图片中可见的结构、哪些还需确认，并把问题复制给商家。分析失败时，用户能识别失败并重试。

本版按“小范围真实试用”设计，不预设已验证的识别准确率、穿衣改善效果或商业需求。教学复现与演示继续保留，但必须明确区分示例和真实结果。

## 2. 范围

保留现有五页：穿衣需求、添加衣服、分析结果、购买确认、理想款对比。沿用原生微信小程序、微信云开发和现有视觉模型接口封装。

本版不新增商品搜索、交易、商家自动联系、多用户档案、历史衣橱、生成服装图片或医学判断。理想款只表达结构建议，固定示意图须说明用途。

首轮验收重点使用上衣、开衫；其他品类可以探索，但没有验证前不宣称支持效果。目标模型、云端配置、真实试用对象及时间待核验或补齐。

实施前先完成 T00 本地模型侦察，约两小时检验坐标、部位识别、不确定性表达、结构输出与耗时，再决定返回结构和展示方式。精确标注是候选方案，不是无条件承诺；侦察不能替代后续云端与真机验收。

首轮进展（2026-09-18）：Qwen3.8-Max 在一张真实商品图上识别出了长袖 Polo 衫，但三次请求均存在明显位置错误；无图对照仍虚构衣服并通过 schema 校验。当前建议采用原照片旁的部位说明，不依赖精确坐标。完整样本验证仍未完成，详见 [侦察记录](model-recon-20260918.md)。

## 3. 主流程

1. 用户填写称呼，至少选择一项动作难点。
2. 用户拍照或从相册选择一张衣服照片，预览后开始分析。
3. 系统根据照片和动作难点分析，展示原照片、可解释的结构发现与待确认事项。
4. 用户进入购买确认页，复制询问话术，收到衣服后按清单试穿。
5. 用户可查看更合适的结构建议，再返回确认页或分析另一件衣服。

示例入口独立运行：使用固定示例衣服、配套数据和明显的示例标识，不调用真实模型。

## 4. 功能需求与验收

### R1 · 穿衣需求

- 支持编辑称呼，默认“妈妈”；只收集称呼和动作难点，不要求疾病信息。
- 保留扣扣子／拉拉链、抬手／套头、弯腰／抬腿三个多选项。
- 至少选择一项才能继续；保存后再次进入可恢复。
- 改变称呼或难点后，后续分析及话术使用新资料，不混用旧结果。

验收：空选无法继续；修改称呼成功；重进页面可恢复；改变资料后重新分析得到对应记录。

### R2 · 添加衣服

- 支持拍照、相册选择、预览和重新选图。
- 上传中、上传成功、上传失败分别呈现；防止重复提交。
- 失败保留照片并提供重试；取消选择不显示错误。
- 选新照片后，旧上传结果不得覆盖新照片或成为其分析输入。

验收：拍照与相册均可完成上传；失败可重试；快速换图时，最终预览、fileID 和分析对象一致。

### R3 · 真实分析、失败与示例

| 状态 | 页面行为 |
|---|---|
| 分析中 | 显示进度提示，避免重复请求 |
| 真实分析成功 | 展示基于本次照片和资料的结果 |
| 缓存命中 | 使用同一照片、同一资料及兼容分析版本的真实结果 |
| 无图、图片下载失败、模型失败或结果不合格 | 显示失败及重试入口，不冒充真实分析 |
| 用户主动选择示例，或开启演示开关 | 展示配套示例照片与数据，持续标明“示例数据” |

- 模型返回先做结构校验，最多尝试两次；失败后可以提供“查看示例”，由用户主动选择。
- 模型须从目标腾讯云境内环境可达，本机经 VPN 调用成功不代表可部署。模型请求预算与云函数执行预算分别配置，整体包含下载图片、重试及其他开销，同时核验客户端等待限制；数值根据侦察和实际云端环境确定，依据见 [TODO 的配置核验说明](todo.md#外部配置核验依据2026-09-18)。
- 重试必须保留原照片和资料；需要重新请求模型时可以绕过缓存。
- 结果来源要传递到购买确认和理想款页面，不能跳页后丢失示例标识。
- 缓存保留现有 24 小时有效期；称呼变化不得返回旧称呼的话术。示例和失败结果不得作为真实结果缓存。

验收：即使模型接口配置完整，示例入口也不会调用模型；没有图片时不会产生“真实分析”；重试使用原 fileID；后续页面仍能区分示例与真实结果。

### R4 · 分析结果与照片标注

- 真实分析展示用户本次上传的照片；示例分析展示配套示例图。
- 展示衣服名称、简短总结、结构发现和待确认事项。
- 若 T00 证据支持精确坐标，标注按实际图片显示区域换算百分比坐标，处理宽高比与留白，不以整个外层容器直接定位；每个可定位发现与对应标注有稳定关联。
- 若坐标不可靠而部位名可用，则采用部位名称对应说明卡片或明确标为结构示意的配图，不将模板坐标冒充原照片定位。部位名也不可靠时取消定位，仅保留有依据的文字；不强行打点。
- 看不清的结构、尺寸和面料弹性应明确为待确认，不要求模型凑足正面或负面结论。

验收：展示方案有 T00 样本证据支持；横图、竖图、方图及衣服偏离画面中心的照片，显示不裁掉关键部位；坐标方案核对标注与文字，部位方案核对部位名称与说明；看不清时明确表达不确定性。

### R5 · 参考评分

本版暂时保留总分及四个分项，用于延续现有界面；结构证据和待确认问题优先于分数。

- 真实模式的分数明确为模型参考估计；示例分数明确属于示例。
- 不宣称存在已验证的动作加权算法。现有示例的算术平均与模型直接输出的总分，要在文档中如实说明。
- 图片无法支持判断的分项允许显示“待确认”；关键依据不足时，总分允许不显示，不能把未知换成零分。
- 不把分数直接转换为“可以买”“保证好穿”等购买保证；建议应能指向具体结构依据。

验收：文档与实现口径一致；缺少尺寸或弹性信息时不强行给出确定判断；无评分时页面仍可使用。

### R6 · 购买确认与理想款

- 提供与本次衣服和动作难点相关的商家问题、完整可复制话术及试穿清单。
- 复制后给出反馈；不自动发送给商家。
- 试穿清单用于用户自查，本版不做试穿记录系统，不把勾选状态当成有效性证据。
- 对比页当前款使用本次照片；理想款展示结构建议，固定配图标为“结构示意”，不假装是生成图或在售商品。
- 理想款不编造分数，不保证某一种扣件对所有人都更省力。

验收：话术对象名与需求页一致；问题对应当前结果；来源标识完整；理想款的示意性质明确。

## 5. 体验与数据边界

- 沿用黑白灰视觉、黑色主按钮和现有语义色约束；保留原生表单组件及足够点击区域。
- 用日常动作描述困难；错误提示告诉用户能做什么，原始技术错误留在日志中。
- 本地分析记录应关联照片、资料快照、结果来源、生成时间及分析版本，避免跨页混用。
- 模型密钥仅放在服务端配置或已忽略的本地调试配置中，不进入小程序包及版本库。
- 上传前用简短说明告知照片将上传并交给模型分析。对外试用前明确云存储访问范围、照片保存期限和删除方式；这三项当前待核验，不在文案中提前作承诺。

## 6. 完成标准

1. 本地自动检查通过，且新增检查覆盖本版的来源区分、缺图、重试、图片关联和资料变更场景。
2. 在微信开发者工具及至少一台手机上走通真实分析、示例、失败恢复三条路径，记录实际环境和结果。
3. 用至少五张有差异的衣服照片检查结构描述及所选定位方案，优先复用 `tools/try-model.js` 保存原始输出与坐标预览，并与 T00 基线对照；本地内容检查不代替真机显示检查。这个数量仅是首轮验收规模，不代表准确率证明。
4. 完成至少一轮自愿参与的目标用户／家庭试用，对照模型预测与实际穿脱观察，记录吻合、误判和无法确认之处；不要求参与者尝试不舒服的动作。
5. 更新说明文档中的部署状态、评分口径及限制。若缺少云端权限、试用条件或证据，对应项保持未完成。
