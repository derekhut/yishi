### 方法与边界

- 复用项目的提示词构造、请求体构造、JSON 解析与 schema 校验；诊断脚本位于 `.local/recon-run.js`。
- 为明确控制变量，诊断请求使用 `reasoning_effort: none` 关闭 Max 思考，保留 `temperature: 0.2`、`max_tokens: 1600`；用 Node fetch 设置 60000ms 总截止时间，PNG 输入声明正确 MIME。
- 上述诊断参数和传输调整未写入生产封装；现有 `tools/try-model.js` 也未新增思考参数。不能把诊断成功说成原小程序链路验证成功。
- 对照版本仅在诊断内修改提示词：取消必须正负都有、允许零标注、取消固定衣服所在范围。保留原始提示词；它是约束组合对照，不能区分每一项修改的独立效果。
- 坐标预览复用 `tools/try-model.js` 的 `drawMarkers` 函数，直接根据已保存返回绘图，没有为出图再次调用模型。
- 资料保持“妈妈 + 扣扣子／拉拉链费劲”，照片里的人物身份不用于推断使用者。

### 发现与证据

**1. 识别衣服类型可用，坐标尚不可靠。**

真实商品图三次均识别为长袖 Polo 衫，但原版首次把“领口纽扣操作难”的点放到 `(50%, 28%)`，落在人物下巴；重复请求又把一个警示点放到 `(50%, 18%)`，落在脸部。约束调整后只给一个警示点，仍为 `(50%, 28%)`，没有解决定位错误。

- [真实图首次预览](../.local/max-photo-baseline.png)
- [真实图重复预览](../.local/max-photo-repeat.png)
- [真实图调整提示词后的预览](../.local/max-photo-relaxed.png)

示意图原版重复请求的袖口点 `(80%, 65%)` 也在衣服外；读取原图对应像素 `(720, 585)` 的 alpha 为 0，与肉眼检查一致。标注落在衣服上本身也不能证明对应了正确部位。

**2. 没有图片也会给出虚构分析，且现有校验放行。**

无图请求返回“圆领套头上衣”、62 分、标注坐标，并称“照片较模糊”。这证明当前提示词和 schema 不能独立保证证据存在；`T02` 必须在缺图／下载失败时中止真实分析，而不是靠模型自觉拒答。

**3. 输出格式合格，不代表事实或建议合格。**

真实图中，对看不清的袖口给出“无束缚”“没有紧绷的松紧带”等正面判断；一次依据商品文案和外观声称“丝光棉材质较软”。调整提示词后仍给出缺少尺寸依据的“尺码友好”80 分。部分试穿建议要求尝试不解扣子套头，不能未经审查直接作为试穿指导。

这支持 T05：区分图片可见事实、商家宣传文字和待确认事项；未知分项不强制打分；建议不得以尝试费力动作来验证模型猜测。删除强制正负结论有帮助空间，但本轮不能宣称它已经消除过度推断。

**4. 当前响应速度需要重新安排超时预算。**

六次带图请求耗时 15.264–17.303 秒，都超过当前配置数字 15000ms。诊断使用不同传输与明确关闭思考，不能据此断言原封装每次必然超时，但原预算明显需要重新测定；若保留两次尝试，还要加上下载、解析和缓存余量。云端与客户端等待预算尚未验证。
