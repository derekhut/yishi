## 卡片 2 · TDD 就四步

```
① 写下这一步做完，我该看到什么
② 写代码
③ 跑检查
④ 红了改，绿了才下一步
```

**唯一一条铁律：红着不许往下走。**

前 3 步（骨架、画像页、拍照页）可以先用「手点一遍」当检查——有界面，点得出来。
**从第 4 步（云函数）开始必须用脚本**——云函数没有界面，你点不出来，只能靠脚本。

写在哪：`tests/check-XXX.js`，最后用 `node tests/run-all.js` 汇总。

## 卡片 3 · 七步清单

- [ ] **1 骨架** → 能打开，白底，标题「衣适」

- [ ] **5 结果页** → 有分数、四根条形、图上有标注

```bash
node tests/run-all.js
```

**绿了才去打下一个勾。**

## 卡片 4 · 让 AI 帮你写代码（提示词，直接复制）

新开一个对话，把下面整段贴进去：

```
我要做一个微信小程序，叫「衣适」，帮行动不便的人挑「好穿」的衣服
（不是挑好看的）。技术栈：原生小程序 + 微信云开发。

请你当我的开发搭档，遵守这几条规矩：

1. 一次只做一步。我说「做第 N 步」，你才做第 N 步，不要一次给我整个项目。
2. 每一步按这个顺序输出：
   先告诉我「这一步做完，我该在界面上看到什么」→ 再写代码 → 最后给我
   一条我自己能跑的验证命令。
3. 优先用小程序自带的组件：view / text / button / image / checkbox /
   radio / picker / switch / navigator / scroll-view 等。
   凡是官方已经提供的「行为」（勾选状态、点击热区、滚动、表单），一律不要自己重做。
   不要引第三方 UI 库（Vant / TDesign / uView），它们会和下面的视觉规范打架。
   只有内置组件确实做不到时，才自己写。
4. 视觉规范：纯白背景；文字三档灰 #1A1A1A / #6E6E6E / #A8A8A8；
   分隔线用 1px #ECECEC；只有「省力」用绿 #3D7A5F、「注意」用琥珀
   #C77D2B，其余一律黑白灰；主按钮是纯黑胶囊形，选中态用描边不用填充色块。
5. 界面文案里绝对不能出现「残障」「残疾」「病人」「疾病」这类词，
   一律说「动作不太方便」。
6. 每写完一步，顺手更新对应的检查脚本。

这七步的顺序是：
1 骨架 → 2 穿衣需求页 → 3 拍照上传页 → 4 分析云函数 →
5 结果页 → 6 购买确认页 → 7 理想款页

现在只回答一件事：第 1 步我该做什么？做完我该看到什么？
```

之后每一次开工，只发一句：

```
做第 2 步。做完我该看到什么？
```

**如果它一次甩给你一大堆代码**，回它：

```
太长了。一次只做一步，先只给我第 2 步，其余的先别写。
```

**如果它写的东西你不理解**，回它：

```
用大白话解释你刚才为什么要这么写，不要贴代码。
```

## 卡片 5 · 三个救命命令

```bash
node -v                       # 环境装好了没
node tests/run-all.js         # 全部检查：7 个套件，每行都要是「0 失败」
node tools/verify-markers.js  # 图上的标注有没有飘出衣服
```

> 判断标准是每行都显示 `0 失败`，不用去记总共有多少项——你每加一个文件，总数就会变。

## 卡片 6 · 最常卡住的六件事

| 你看到的 | 原因 | 怎么办 |
|---|---|---|
| 报错 `100129`，自动预览失败 | `cloudfunctions/` 下有**空目录**，或 AppID 还是测试号 | 每个云函数目录至少要有 `index.js` + `package.json`；换成真实 AppID |
| 显示「cloudfunctions（未选择环境）」 | 没开通云开发 | 点顶部「云开发」开通 → 拿环境 ID → 填进 `utils/config.js` |
| 部署成功了，控制台却「暂无云函数」 | 正常，云函数不会自动同步 | 右键 `cloudfunctions/analyze` → 上传并部署：**云端安装依赖** |
| 点上传一直转圈 / 提示「请拍一张照片」 | 云环境没通 | 先走「示例数据」入口，别卡在这 |
| 测试说出现了「残障」这种词 | 你把禁词写进注释或说明里了 | 改写成描述意图，比如「不要用标签化的称谓」 |
| 汇总显示全绿，但新写的测试没跑 | 汇总脚本是**硬编码清单** | 改成扫描目录自动发现测试文件 |

## 卡片 7 · 答辩三句话

被问到就照这个说，别现场编：

**「为什么不收集疾病名称？」**
> 用医学词汇定义用户，是把人变成标签。我们只关心动作能力，所以问「哪些动作费劲」就够了。

**「分数是怎么算的？」**
> 按这个人勾选的难点加权。同一件衣服换个人分数会变，所以界面上明确写了它是对这个人的参考值，不是绝对质量分。

**「AI 分析失败了怎么办？」**
> 四层保险丝：严格校验 → 自动重试一次 → 退回内置示例数据 → 外层兜底。退到示例数据时界面会如实标注，演示不会崩。

## 卡片 8 · 演示前的紧急开关

万一现场模型不稳定，改一个字就能回到 100% 可控状态：

```js
// utils/config.js
FORCE_EXAMPLE: true    // 强制走内置示例数据，不调模型
```

改完重新编译。**演示前一定要知道这个开关在哪。**
